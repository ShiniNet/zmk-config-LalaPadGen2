### REQ-195 追記3: BT 切り替えを「かな長押し」のレイヤーへ

- かなキー（位置 38）の長押しで入る **L4 Mouse** に置いた。右手の上段（位置 5〜9）に左端から **BT 1〜5（BT_SEL 0〜4）**、その下の段（位置 15〜19）に **出力先切替（USB/BT）・再起動・書込モード・BT 登録解除・BT 全解除**。下の段の並びは Gen2 標準の System レイヤーの順（出力先 → 再起動 → 書込モード → 登録解除 → 全解除）を保った

- 競合はない: L4 のこの 10 か所は .vil でも Gen2 でも空き（KC_NO）だった。移設したキーはない

- トラックパッドに触れたときに自動で L4 に入る設定（auto-mouse）は Gen2 にないので、トラックパッド操作中に BT を誤って切り替えることはない

## REQ-195 で足したこと（2026-11-26、接続先 OS で変わるキーマップ）

Bluetooth プロファイル 4・5 に接続しているあいだは Windows 用の割当、プロファイル 1〜3 と USB では Mac 用の割当（REQ-194 のまま）になるようにした。

### 追記で直したこと（2026-11-26、稜太の追記・決定）

1. **プロファイル 5（BT_SEL 4）を選べるようにした**: REQ-194 版の System レイヤーには BT_SEL 0〜3 しかなかった。System レイヤーの位置 19（BT 4 の下、元は空き）に BT_SEL 4 を置いた。プロファイル数の上限は、右手側の `CONFIG_BT_MAX_PAIRED=6`（左手 1 台を引いて 5）で、ZMK の既定値どおり 5 だった（4 ではない）。設定を `lalapadgen2_right.conf` に明示した。あわせて同時接続数 `CONFIG_BT_MAX_CONN` を Gen2 の既定 5 から 6 に上げた（接続先 5 台＋左手 1 台。5 だと 5 台目の接続先が同時につながれない）
2. **L5（QWERTY）と L6（別のカナ配列）を削除した**（REQ-194 の判断点 (j) は「削除」で確定）: 変換時に .vil のレイヤー 5・6 を移さない（`tools/vil2zmk.py` の `DROP_LAYERS`）。**レイヤー番号が変わった**:

| 前（REQ-194・REQ-195 当初） | 今 |
| --- | --- |
| L0 Base〜L4 Mouse | 変わらない（L0〜L4） |
| L5 QWERTY・L6 Kana2 | 削除 |
| L7・L8・L9（空き） | L5・L6・L7（空き） |
| L10 System | **L8 System**（Num と Nav の同時長押しで出るのは同じ） |

L0〜L4 と System の中身、コンボ、マクロ、os-morph は削除前と同じことを確かめた。トラックパッドの低速モード（layer 1・2）は番号が変わらないので影響なし。キーボードの LED（いちばん上のレイヤー番号の回数だけ点滅）は、System に入ったときの点滅が 10 回から 8 回になる

### 採用した方式: (b) Bluetooth プロファイル連動（自作の behavior「os-morph」）

| 候補 | 結論 |
| --- | --- |
| (a) ホスト OS の自動判定 | 採らない。ZMK（v0.3）に OS 判定の機能はない。QMK の os_detection は USB の挙動から推測するもので、Bluetooth では使えない |
| (b) プロファイル連動 | **採用**。ZMK 標準にはないので、このリポジトリに小さな behavior を足した（外部モジュールは追加しない） |
| (c) 手動の切替レイヤー | 採らない。切り替え忘れで Mac 側でも Windows の割当が出る（誤爆）おそれがある |

- 仕組み: `src/behaviors/behavior_os_morph.c`（約 130 行）。`bindings = <Mac 用>, <Windows 用>` を持ち、**キーを押した瞬間**の接続先（ZMK の endpoint）を見てどちらを押すか決める。押したときに選んだ割当を位置ごとに覚え、離すときは同じ割当を離す
- Windows になる条件: 接続が Bluetooth で、プロファイル番号が `CONFIG_ZMK_BEHAVIOR_OS_MORPH_WIN_PROFILES`（既定 0x18 = ZMK の BT_SEL 3・4 = 1 始まりの 4・5）に入っているときだけ。それ以外（プロファイル 1〜3、USB、接続先が決まる前）はすべて Mac 用。Mac 側で Windows の割当が出る経路はない
- Mac 側は変えていない: Windows で変わるキーだけを os-morph に包み、その 1 番目には REQ-194 の割当をそのまま入れた。`tools/gen_visualizer.py` で Mac 側に展開したキーマップが REQ-194 版と全レイヤー・全位置で一致することを確かめた（違いは System レイヤーに足した BT 5 の 1 キーだけ。そこは元々空き）。コンボ、マクロ、条件付きレイヤーも REQ-194 のまま（レイヤーの番号は追記2 の L5・L6 削除で変わった）
- レイヤーを増やす方式（Windows 用のレイヤーを重ねる）は採らなかった。キーボードの LED が「いちばん上のレイヤー番号」の回数だけ点滅する設定（Gen2 標準）なので、Windows では点滅が 10 回以上になり、System レイヤーの番号も変わって Mac 側の点滅回数まで変わるため
- ファイル: `zephyr/module.yml`（cmake・kconfig・dts_root を追加）、`CMakeLists.txt`、`Kconfig`、`dts/bindings/behaviors/lalapad,behavior-os-morph.yaml`、`src/behaviors/behavior_os_morph.c`。キーマップ側は `tools/vil2zmk.py` の `OS_MORPHS` の表から生成する

### 制約

- **OS そのものは判定しない**。プロファイル 4・5 に Windows 機を、1〜3 に Mac を登録する運用が前提。Mac をプロファイル 4・5 に登録すると Windows の割当になる
- **USB 接続は常に Mac 用**。Windows 機に USB でつなぐと Mac の割当になる（Windows で使うときは Bluetooth のプロファイル 4・5 で）
- 切り替わるのはキーを押した瞬間。押したままプロファイルを切り替えても、そのキーは押したときの割当のまま離れる
- Windows 側の IME: 無変換＝IME オフ、変換＝IME オンにするには、Microsoft IME の設定（キーとタッチのカスタマイズ）で無変換・変換キーにその機能を割り当てる必要がある
- ⌘ の位置が Ctrl になるので、⌘Tab は Windows では Ctrl+Tab になる（アプリの切替は Alt+Tab ＝ Opt の位置＋Tab）
- 輝度キーは、Windows ではノート PC の画面でしか効かないことが多い
- ZMK Studio でキーマップを編集すると、os-morph のキーは中身（Mac 用・Windows 用）を Studio から変えられない。変えるときは `tools/vil2zmk.py` の `OS_MORPHS` を直して作り直す
- System レイヤーに **BT 5**（BT_SEL 4、位置 19）を足した。Gen2 標準は BT 1〜4（BT_SEL 0〜3）までしか選べなかった。プロファイル数は 5（右手側の BT_MAX_PAIRED 6 − 左手 1）、同時接続数は 6（BT_MAX_CONN、Gen2 の既定 5 から引き上げ）
- ビジュアライザーは「接続先」で Mac / Windows を切り替えて表示する。Windows 表示では Mac と違うキーに紫の枠と「Win」の印が付き、「接続先 OS で変わる割当」の表にそのレイヤーの違いが並ぶ。System レイヤーの BT キーは 1 始まりで「BT 4（Win）」のように表示する

- 右下段に修飾キーは置かない。右Ctrl の跡（41）に Esc。右⌘・右Opt の跡（39・40）に Delete と 戻る を仮置き（Num レイヤーだけは .vil どおり : と /）
- 右親指の Shift（37）: タップ＝Tab、長押し＝Shift（Base レイヤー。Num〜Mouse レイヤーは .vil どおりタップ＝Space、Fn は App）
- 5方向スイッチの左右: 左手＝← →、右手＝左がコピー（⌘C）・右がペースト（⌘V）。押し込み・上下は変更なし（Sleep は「そのまま」で確定）
- Num レイヤーのテンキーを右へ1列ずらした（下の表）

| 位置 | 前 | 今 |
| --- | --- | --- |
| 5・6・7・8・9（右上段） | 7・8・9・＋・− | ＋・7・8・9・− |
| 15・16・17・18・19（右中段） | 4・5・6・＊・／ | ：・4・5・6・／ |
| 25・26・27・28・29（右下段） | 1・2・3・0・． | 0・1・2・3・． |

数字はすべてテンキーのキー（KP）。「：」は JIS の : のキー（Num レイヤー左手の : と同じ）。テンキーの ＊ は外した。JIS では ⇧＋: で ＊ が出る（＋ も ⇧＋; で出る）。

## 4. Gen2 標準ファームウェアから外したもの・残したもの

- 外した: QWERTY のベース層、Gen2 標準の同時押し（Q+W=Esc・A+S=Tab）、5方向スイッチの矢印、`=`/`-` の mod-tap（mt2）、タップダンス（td_mo12）、Windows 向けのトラックパッド割当

## 5. トラックパッド（macOS の作法に合わせた割当）

左右のパッドで同じ割当。全レイヤー共通（Gen2 標準にあった Num レイヤーだけの割当 ⌃⌘←/⌃⌘→ は外した）。

| 操作 | Gen2 標準（Windows 向け） | 今の割当 | Mac のトラックパッドでの同じ操作 |
| --- | --- | --- | --- |
| 1本指で移動 | カーソル移動（指を離した後も慣性で滑る） | カーソル移動（慣性なし） | カーソル移動（慣性なし） |
| 2本指で上下左右 | スクロール（慣性あり） | 変更なし | スクロール（慣性あり）。向き（ナチュラル）は Mac の設定で決まる |
| 1本指でタップ（MB1） | 左クリック | 変更なし | タップでクリック |
| 1本指でタップして、すぐ触れたまま動かす | ドラッグ | 変更なし | 「ドラッグにトラックパッドを使用」のダブルタップドラッグ |
| 2本指でタップ（MB2） | 右クリック | 変更なし | 副ボタンのクリック |
| 3本指でタップ（MB3） | 中クリック | 調べる（⌃⌘D） | 「調べる＆データ検出: 3本指でタップ」 |
| 2本指・3本指のタップドラッグ | 右・中ボタンを押したまま | 切った | （Mac にはない） |
| 3本指で右へスワイプ（MB4） | 戻る | ⌃←（左の操作スペースへ） | 3本指で右へスワイプ＝フルスクリーンアプリ間のスワイプ |
| 3本指で左へスワイプ（MB5） | 進む | ⌃→（右の操作スペースへ） | 同上 |
| 3本指で上へスワイプ（MB6） | Win+Tab | ⌃↑（Mission Control） | 3本指で上へスワイプ |
| 3本指で下へスワイプ（MB7） | Win+D | ⌃↓（アプリケーションウインドウ） | 3本指で下へスワイプ（App Exposé） |
| 2本指でピンチ（ZMOD） | Ctrl＋ホイール | ⌘＋ホイール | ピンチで拡大・縮小 |

- スワイプの向きと MB4〜7 の対応は、ドライバー（zmk-driver-iqs9151 v1.0.0）の実装（右→MB4、左→MB5、上→MB6、下→MB7）と Gen2 の説明書（HowtoUse）の既定割当表で確かめた。説明書の Num レイヤーの表だけは左右が逆に書かれているので、実機での確認が要る
- ⌃←・⌃→・⌃↑・⌃↓ は macOS のキーボードショートカット（Mission Control）の既定値。システム設定で切っていると効かない
- 2本指の左右スワイプでのブラウザの戻る・進む（Mac の「ページ間をスワイプ」）は、ファームウェアからは横スクロールとしてしか送れないため再現できない

## 6. タップホールドの設定

.vil の設定（QMK Settings）: Tapping Term 250 ms、Permissive Hold オン、Hold On Other Key Press オフ、Chordal Hold オン、Flow Tap 120 ms、Combo time out 10000 ms（REQ-194 の .vil）。コンボ2件の待ち時間は、判断点 (k) の決定で ZMK 標準の 50 ms にした（.vil の値は使わない）。

| .vil | ZMK |
| --- | --- |
| Tapping Term 250 | tapping-term-ms 250 |
| Permissive Hold | flavor "balanced" |
| Flow Tap 120 | require-prior-idle-ms 120（直前のキーから 120 ms 以内ならタップ扱い） |
| Quick Tap Term（未設定＝Tapping Term） | quick-tap-ms 250 |
| Chordal Hold | Shift 付き Space（mod-tap）だけ、反対の手のキーか親指キーと重なったときにホールドにする（hold-trigger-key-positions、判定はキーを離したとき）。レイヤータップ（英数・Enter・BS・かな）には掛けていない |

Chordal Hold をレイヤータップにも掛けると、Enter 長押しで左手の数字を速く打ったときに Enter が出てしまう。Cornix 側で親指キーがどちらの手として扱われていたかは .vil から読めないので、上の形にした。
